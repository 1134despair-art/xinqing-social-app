## 三、交给后台开发确认的两类事实

T01 后台服务清单：确认正式环境使用哪些短信、AI 生成、存储/媒体和外部审核服务，填写产品名、接收方公司、实际发送的信息及官方隐私链接。自建或未启用的环节注明即可，不需要把场景用途重写一遍。确定产品后再匹配其官方专用规则，不能仅因多数服务使用腾讯云就全部写成腾讯云。

T02 部署地区：确认业务服务器、文件、备份及后台服务的实际存储和处理国家/地区，是否存在境外处理或远程访问。若全部在中国大陆，可经核实后统一写明；存在例外则单列接收方及依法需要的跨境说明。

```text
T01：
短信：产品名 / 接收方公司 / 发送的信息 / 官方隐私链接
AI 生成：产品名 / 接收方公司 / 发送的信息 / 官方隐私链接
存储与媒体：产品名 / 接收方公司 / 发送的信息 / 官方隐私链接
内容审核：自建、未启用，或产品名 / 接收方公司 / 发送的信息 / 官方隐私链接

T02：
业务服务器、数据库：国家/地区
文件、生成媒体、分发和备份：国家/地区
上述各后台服务：国家/地区
境外处理或访问：无，或列明具体环节及接收方
```

无需提供密钥、控制台密码、验证码或真实用户数据。开发另需核对服务实际启用范围、删除和留存配置，以及是否存在额外训练或人工查看，确保不超出最终政策的承诺；这些属于实施核验，不再拆成需要你填写的一长串问题。

## 四、上架前必须落实的功能

目前不能据文档认定已具备提审条件。本次只修改协议及核对文档，以下问题尚未修复：

- 协议展示与收集前告知：应用内关于页仍是旧版简述，需接入完整新协议；确保未登录也能稳定查看。发送验证码前未检查相应隐私确认，需要补上收集手机号前的告知与所需同意，并验证首次启动、拒绝同意时的 SDK 行为。
- 账号注销：未找到应用内注销入口或后台接口。苹果要求可以在 App 内发起账号删除，普通 App 不能仅让用户发邮件或找客服。需完成入口、后台删除及结果通知，再同步修改协议中的当前注销方式。
- 用户内容安全：有心情/评论举报，但未找到屏蔽骚扰用户功能。需落实不当内容过滤、举报处理、用户屏蔽和公开联系渠道，并用正式后台验证。
- AI 处理：生成开关只切换状态，未找到发送数据前针对具体第三方的说明和明确同意；须覆盖新建及已有心情生成入口，并核实正式生成服务及生成合成内容标识。
- 权限与资料最小化：Android 声明了手机状态、系统账户、日志、系统设置等额外权限；需按实际能力清理并核对正式安装包。iOS 权限说明需与头像、客服及录音场景一致。性别、年龄当前必填，应说明必要性或调整为可选。
- 反馈受理：帮助反馈、视频替换表单目前仅存本地，成功提示不代表后台收件。需接通真实受理渠道或修正入口和提示；B03 邮箱与权利申请处理流程也需实际可用。
- 未成年人：年龄字段允许 1 至 120 岁，未发现完整儿童授权流程。若接纳不满 14 周岁用户，应落实监护人同意和儿童个人信息规则；若不接纳，应实施与产品范围一致的年龄限制。不能只依赖一般监护人提示。

提交前用正式安卓/iOS 安装包验证同意、拒绝权限、录音、生成、举报、屏蔽和注销流程；核对商店隐私申报与真实 SDK 行为。两份协议还需部署为无需登录可访问的稳定 HTTPS 页面，并填写到 App 和商店后台。现有本地 HTML 不能直接充当商店要求的线上隐私政策网址。

详细代码证据与处理建议见 [内部技术核对记录](code-audit-notes.md)。本次未取得后台实现或正式安装包，不把源码中有入口等同于线上服务已经可用。
